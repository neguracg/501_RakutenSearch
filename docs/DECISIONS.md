# DECISIONS


## 2026-11-04 説明ページ
- 対象は個人の買い物全般。ソーラーパネルは最初の検索例。
- ユーザーの指示に基づき既存リポジトリを利用し、GitHub Pagesに静的説明ページを公開する方針。
- CLI本体・認証情報・商品データは公開ページへ含めない。
- API利用条件の適合確認と接続試験は別途必要。

## 2026-11-05 Phase 1 着手
- 最終形は楽天・Yahoo!・Amazon・ヨドバシの横断比較。モール固有処理は adapter に閉じ込める（SPEC §3）。
- ChatGPT 接続は MCP サーバーを主軸（個人プランでカスタムGPT新規作成不可のため GPT Actions は採らない）。Plus からの実接続は未検証。
- 定番品（例: 洗剤の詰め替え、単3電池、飲料水）の入り数・サイズ違い比較を中核機能として Phase 1 に含める。
- 単価・最安判定は誤ると実害が出るロジックのため、独立試験（ブラインド）で判定する。
- 楽天規約の個人専用運用は未解決のまま。公開アプリと偽装する方法は採らない。

## 2026-11-05 公開Webアプリ化（#920）
- 楽天規約 第10条(10) への対応として、腱さんが「B（誰でも開ける公開Webアプリ。VPS・ログイン無し）」を選んだ。
- 楽天に登録するアプリは公開Web `https://app.negura.website/kaimono/`。CLI・MCP は同じアプリの運営者用ツールという解釈。偽装はしない。
- 公開Webは search / compare のみ。定番品は出さない。サーバー側が楽天 API を呼び、ブラウザにキーを渡さない。
- 流量保護（1秒1回の直列化・10分キャッシュ・IP別回数制限）と規約表示（クレジット・運営者責任・価格在庫の注意）を必須とする。SPEC §11・§12（AC-W1〜W8）に反映。

## 2026-11-05 AI からの入口（#920・#923）
- ChatGPT（Web/アプリ）は PC 内の stdio MCP に繋げないため、公開アプリに Streamable HTTP の MCP `{BASE}/mcp`（認証なし）を同居させる。ChatGPT・Claude Code・Claude デスクトップ/Cowork・Codex はすべてここへ繋ぐ（腱さん「規約違反ならそっち優先」「これで進めて」）。
- 公開 MCP の道具は search_products / compare_offers の2つ。結果にクレジット・運営者表示を必ず付ける。流量保護は Web と共通の層（guard.py）。

## 2026-11-05 汎用ツールとして作り直す（腱さん指摘）
- 「汎用ツールなのにトイレットペーパー・倍巻きの話ばかり」の指摘で、数量・比較からカテゴリ固有の知識を外した。道具は商品の意味を持たず、「個数×内容量の読み取りと単位換算（表）」と「含む語・除く語」だけを持つ。仕様の違いは AI 側が判断する（SPEC §7・§8）。

## 2026-11-05 数量の信頼度は「解釈の一致」で決める
- 規則を足すたびに別の誤読が出た（誤り 16→50 件に悪化）ため、全ての読み方が同じ総数を指す時だけ高信頼にし、食い違えば単価不明に倒す方式へ（SPEC §7 P0）。数え語は直後の文字で判定（P5）。
- 受入条件は実在らしい題名コーパス（tests/corpus。383件）で高信頼の誤り0・単価不明20%以下（AC-Q1）。
- WP7 で題名読み取りの規則追加はいったん打ち止め。次は実題名で誤り率を測ってから決める。既知の限界は SPEC §7・kadai-list。
