# 指示書 WP8 — E2E試験（ChatGPT起点 80件・2026-11-06）で見つかった道具側の P0 違反の修正

## 背景（オーケストレータ判断）

腱さんが ChatGPT 通常チャット → 公開MCP → 楽天API の E2E 機能試験 80件を実施（PASS 38 / FAIL 30 / BLOCKED 12）。
FAIL の大半は「商品の意味」（カテゴリ違い・W/Wh・炭酸/非炭酸・単3/単4・24本指定に48本）で、SPEC §7・§8「道具は商品の意味を持たない」により**この WP の対象外**（方向性は腱さんへ別途 ask 中。触らない）。

この WP は、そのうち**道具自身の契約（SPEC §7 P0「全ての読み方が同じ総数を指す時だけ high」）に違反している**ものと、**HTTP 400** だけを直す（変更分類 A）。WP7 の「規則追加の打ち止め」は、ここで言う実題名での測定が済んだため、**P0 違反を low 側へ倒す修正に限って**解除する。**high に倒す規則は足さない**（失敗の向きは常に「単価不明」）。

## 着手前5問（オーケストレータの答え。ワーカーは実装前に現物で確かめ、違えば報告）

1. 同じ知識の場所: 数量の読み取りは `src/shopping/quantity.py` の `parse_quantity` だけ（pricing.py は結果を使うだけ）。HTTP 400 の検査は `src/shopping/inputs.py`（`fits_limit` と同じ所有者）。
2. 同種の既存機能: P5 の「捨てた数の検査」（個数だけが対象）。今回の穴は**同じ機構の取りこぼし** —— 題名に現れた「数字＋単位/数え語」のうち、トークン化の段階で候補にすら入らない物（前の文字が `_`・`大` 等、後ろが文字の `12Rダ`、`/` で並ぶ択一、【】内の総数と後続の鎖）が P0 の一致判定に乗らない。**語のリストで個別に潰さない**（BUGLOG A3・A4 の再発型）。
3. 引っ越しではない。
4. 過去の類似: BUGLOG A1・A1′・A2・A3・A4、SPEC §7 P0〜P7・既知の限界 R1〜R3。必ず読んでから書く（規則の足し算で誤り 16→50 件に悪化した経緯あり）。
5. 所有モジュール: 数量＝quantity.py、入力の検査＝inputs.py。そこだけで済むはず。2箇所以上に散るなら報告。

## 実装

### WP8-1 数量: 捨てた候補の検査を、内容量と択一にも広げる（P0 の徹底）
- 機構を1つ言語化してから直す: 「**題名に現れた『数字＋表にある単位・数え語』は、採用しなかった物も含めて全部 P0 の候補にし、採用した総数（個数・内容量）と食い違えば low**」。現状は個数（数え語）の一部だけがこの検査に乗っている。
- T1〜T6 がすべて期待どおりになること。T7 は 40本 high のまま。
- 既知の限界 R1〜R3・C3 は**この WP で直さない**（触って挙動が変わる時は報告）。
- コーパスの退行禁止: `tests/test_title_corpus.py`（383件）の高信頼の誤り 0 を維持。単価不明率は現状 17.5% → **22% 以下**。超える時は実装を止めて、どの題名が low に落ちたかの一覧を報告（オーケストレータが判断する）。
- ヨコテン（必須）: 機構ごとに、同じ形の別の言い回しを各3件以上自作して試験に入れる（例: 【24本】…24本 2ケース／最大1kg … 500g／約500g〜1kg／_50m・_30m／6R入・18Rダブル／2個/4個セット／100g・200g・300g から選べる）。真値どおり high のまま残るべき形（「12ロール×4パック(48ロール)」「500ml×24本」「24本 (500ml×24)」「200g×5袋」等の既存の言い直し）が low に落ちないことも同じ表で固定。
- 実題名 T1〜T7 は `tests/corpus/unseen4_patterns.py` として既存コーパスの書式（compare.py の真値形式）で追加し AC-Q1 に含める（T1・T5・T6 の真値は曖昧＝low が正、T2 は 12×30m、T3 は 48本×500ml、T4 は 12本×2L、T7 は 40本）。

### WP8-2 HTTP 400: 半角1文字の語
- 実測（2026-11-06 オーケストレータ）: 楽天API は keyword の空白区切りの語に**半角1文字**が含まれると HTTP 400（`EcoFlow DELTA 2`・`EcoFlow DELTA 2 対応`・`単3 a` → 400、`EcoFlow DELTA2` → 112件）。楽天の公式仕様の記述（「半角2文字以上／全角1文字以上」相当）を一次資料で1回確認し、URL を WORKLOG に残す。確認できなければ実測を根拠と書く。
- 送る前に検査し、利用者に理由が分かる誤りを返す（kind 例: `keyword_term_too_short`。「『2』のような半角1文字の語は楽天で検索できません。『DELTA2』のように前の語とつなげてください」相当の文言）。**勝手に語をつなげたり捨てたりしない**（意味が変わる）。NG キーワード（除く語）も同じ規則か確認して揃える。
- 公開Web・公開MCP・CLI の3つの入口で同じ検査が効くことを試験で固定（所有者は inputs.py の1箇所）。
- 注意: 並走中の別セッションが公開MCPの pages（mcp_server.py・orchestrator 周り）を触っている。WP8-2 は inputs.py と adapter のエラー文言に閉じ、mcp_server.py の pages 関連は触らない。
