# 指示書 WP10 — 単価の外れ値を「要確認」にして最安から外す（結果側の網）

## 背景（オーケストレータ判断・腱さん指示 DECISIONS 2026-11-06「数量の読み取りは割り切り、穴は仕組みで塞ぐ」）

題名からの数量の読み取りは表現が無限にあり、規則では塞ぎ切れない（SPEC §7 R1〜R7 が既知の残り）。E2E で見つかった誤りの多くは、言い回しはばらばらでも**結果が「単位価格だけが他の候補より桁違いに安い」**という同じ形になる（型番 80L のインク＝80,000ml、紙幅 109mm を 1 ロールの長さ、48本の二重計上、`ICBK80L 80L×2個`＝R7）。
言い回しではなく結果の側で拾う網を1つ足す。**失敗の向きは「本物の桁違いの掘り出し物が最安に出ない」**（候補一覧からは消さず、理由付きで残す）。

変更分類 B（仕様変更）。SPEC §8 を同じコミットで更新する。

## 仕様（案。数値は実データで裏付けてから確定）

- 対象: `pricing.compare` の単位価格グループ（basis の次元が同じ・単位価格が出ている候補）。
- 判定: グループの候補が **N 件以上**ある時だけ、単位価格の**中央値**を取り、`unit_price < 中央値 / K` の候補を「外れ値（要確認）」とする。N 件未満のグループには掛けない（中央値が当てにならない）。
- 外れ値の扱い:
  - `cheapest_unit_price`・`cheapest_for_quantity`（数量を使う2つ）の選定から外す。`cheapest_price`・`cheapest_total`（数量を使わない）は変えない。
  - 候補一覧からは消さない。候補ごとに外れ値である印（例 `Offer.unit_price_outlier: bool`。名前は既存の命名に合わせて決めてよい）を付け、公開Web の表・公開MCP の返却・CLI の表示に出す（「単価が他の候補と桁違いに安い。数量の読み違いの疑い。商品ページで確認」相当の文言）。
  - caveats に件数の1行（例「単価が他の候補の 1/K 未満で、数量の読み違いの疑いがある候補: N件（単位価格の最安から外しています）」）。0件なら出さない。
  - 外れ値を除いた後に最安が無くなる時は `cheapest_unit_price=None`（偽の最安を出さない）。
- **N と K は出典か実測で決める（BUGLOG 2026-11-06 の「出典の無い上限」の再発防止）**: 初期値の案は N=5・K=10（「桁違い」＝1桁）。実 API で 20 検索語程度（水・お茶・トイレットペーパー・歯磨き粉・洗剤・米・コーヒー・電池・インク・ポータブル電源・ケーブル等。1秒1回・pages=1）を取り、high の候補だけで「中央値に対する比」の分布を出す。(a) 本物の商品で中央値の 1/K を下回る件数（誤検知）(b) 既知の誤り（R5〜R7 の形・コーパスの WRONG 相当）を拾える件数、を表にして、K と N を決める。根拠の表は WORKLOG と SPEC §8 の注に残す。誤検知が多い時は K を大きくする方へ（安全側の意味が逆になる点に注意: K が小さいほど網は広く、本物の安値を外す）。決めかねる時は表を報告して止める。
- 高すぎる外れ値（中央値×K 超）は今回は扱わない（最安の誤りにならないため）。

- 単体: グループ N 件未満で掛からない／中央値の 1/K 未満だけ印が付く／印の付いた候補が `cheapest_unit_price`・`cheapest_for_quantity` に選ばれない／`cheapest_price`・`cheapest_total` は変わらない／全部が外れ値になる形は無いことの確認（中央値の定義上）／caveats の件数行。
